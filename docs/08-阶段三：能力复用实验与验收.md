# 阶段三：能力复用实验与验收

版本：v0.1 · 第三阶段配套实验  
配套：[07-阶段三：RAG、记忆、Skills与MCP](07-阶段三：RAG、记忆、Skills与MCP.md)

本文件给出实现顺序、虚构资料夹具和验收标准，不创建项目代码、知识索引、记忆记录或 MCP 进程。

## 1. 最终要展示什么

同一个 Java Runner，用不同能力配置完成两个任务：

- **资料分析**：沿用阶段一、二的 CSV 比较，生成有计算依据的报告。
- **产品调研**：从知识资料查功能，用 MCP 查询当次供应状态，生成有引用的选型建议。

再做第三次独立 Run，验证用户确认的展示偏好可以复用，但没有读取前一次的聊天历史或把旧产品状态当新事实。

看到两个任务使用相同循环，比做一个工具很多的演示更能证明主体可扩展。

## 2. 夹具是虚构产品，不需要真实企业系统

本实验产品名为“星舟知识助手”，纯属教学资料。候选型号只有 LITE 与 LOCAL，不关联现实产品承诺。

### 2.1 调研任务简报

> 我需要一个可在内网运行、日常处理资料不依赖公网连接的版本。请在 LITE 与 LOCAL 中选择当前可供应的型号，说明运行方式、升级限制和证据；如果没有符合条件的型号，明确说明，不用勉强推荐。

TaskBrief 固定：

| 字段 | 取值 |
|---|---|
| candidates | LITE、LOCAL，集合已明确 |
| requirements | 内网运行、日常处理不依赖公网 |
| currentStatusRequired | 是，状态观察有效期为 60 秒 |
| deliverables | selection_report |
| allowedCollection | starboat-public |
| allowedMcpTools | catalog_get_product_status |
| permittedOutcomes | 推荐有依据的合格型号；或基于完整候选检查得出“暂无匹配” |
| evidenceGap | 资料或状态缺失时说明缺口并等待/停止，不把未知当不支持 |

如果用户额外问“是否支持手机蓝牙离线同步”，资料没有依据，答案应是“未找到支持该结论的资料”，不是“已证明不支持”。

### 2.2 知识来源清单

初始集合使用下列 12 份小型 TXT/Markdown 文档，逐份登记 sourceId、sourceVersion、状态、业务适用范围和内容摘要。正文需清楚表达表中事实，不把标准答案直接放进 Agent 的系统 Prompt。

| ID | 主题 | 正文应包含的事实 |
|---|---|---|
| KB01 | 产品目录 | 本实验仅评估 LITE 与 LOCAL，目录不证明实时供应状态 |
| KB02 | LITE 运行方式 | 托管云端版本；日常查询需要公网；不提供本地部署 |
| KB03 | LOCAL 运行方式 | 支持部署到企业内网；日常导入与问答可不连接公网 |
| KB04 | 资料格式 | 两个型号均支持本文约定的 TXT/Markdown；不承诺未列出的格式 |
| KB05 | LOCAL 升级方式 | 离线环境需人工导入已签名升级包；不自动从公网获取更新 |
| KB06 | 安全边界 | 选型资料不等同于安全认证或企业合规保证 |
| KB07 | 网络说明 | “内网离线运行”指日常业务不依赖公网，不代表机器没有任何网络接口 |
| KB08 | 历史限制 | 旧版 LOCAL 曾要求周期联网；明确标识已被 KB03 当前适用版本替代 |
| KB09 | 规划草稿 | 设想未来自动离线升级，明确标为未发布草稿，不能作为现有能力 |
| KB10 | 编辑器主题 | 与部署方式无关的外观偏好介绍 |
| KB11 | 部署术语 | 自托管、私有部署、放在自家机房在本实验检索中是相关表达，不自动证明某型号支持 |
| KB12 | 状态说明 | 文档不维护即时供应；查询结果仅代表其标注时间，应使用状态工具 |

另建一个不在允许范围内的 starboat-private 集合，放一条容易命中但禁止本任务读取的资料，用来测试过滤。不要用真实机密；内容也应是虚构的测试标记。

默认版本把 KB08 标为历史、KB09 标为草稿；若问题明确询问历史，可以在另一个受控任务中使用，但不能用于当前产品推荐。

业务有效范围来自受控导入信息并和正文核对；不能信任模型自行修改 sourceStatus。出现两份都声称有效却冲突的资料，必须暴露冲突，而不是按文件名或分数裁决。

### 2.3 标准结论

当 MCP 返回两个型号均可供应时：

- 推荐 LOCAL，依据 KB03 的部署与日常离线能力。
- 说明 KB05 的人工签名包升级限制，不能宣传自动离线升级。
- LITE 不符合内网本地运行要求，依据 KB02。
- 当前供应依据必须来自本 Run 的状态观察，不引用 KB01 或上一次报告代替。
- 不声称获得安全认证、支持蓝牙同步或保证资料覆盖全部企业场景。

当 LOCAL 不可供应而 LITE 可供应时：当前两个候选中没有同时满足约束且可供应的型号。因为 TaskBrief 事先允许这种结论，可以据完整证据完成“暂无匹配”报告；不能把 LITE 推荐成符合离线需求。

若 LOCAL 状态查询失败，则是关键状态未知，不是“暂无匹配”的证明。

## 3. Skills 实验：先验证换方法，不改引擎

### 3.1 配置两个受控 Skill

| Skill | 主要方法 | 允许能力 | 检查器 |
|---|---|---|---|
| data-analysis | 查字段与口径→计算→解释→报告 | 原分析和工作区工具 | 计算范围、数值来源与产物版本 |
| product-research | 分清需求→检索回读→查状态→比较→报告 | 知识、只读 MCP 与工作区工具 | 文档主张、状态时效与候选覆盖 |

Skill 的 instructions 可以建议步骤，但不能改变 TaskBrief。声明某工具却未被应用批准时，装配失败，不让模型临时安装工具。

### 3.2 渐进加载检查

- 列出 Skills 时只读登记元数据，不把两套正文同时塞进上下文。
- 选择 product-research 后，只有该 Skill 正文进入方法区。
- 引用模板和长参考文件时，才通过 readSkillReference 读取必要片段。
- Skill 文件/参考文件在当前 Run 中变化时，使用已锁定快照或明确停止，不能静默混版；本实验建议复制有界快照并核对摘要。

恶意或不兼容变体：scripts 目录要求执行脚本、相对路径越界、allowed-tools 请求未批准工具、正文要求忽略来源校验。前几类由加载器拒绝；正文不能让程序控制边界失效。

验收不是“成功读出 SKILL.md”，而是新任务沿用同一 Runner，且没有把新领域条件写进循环。

## 4. RAG 实验：检索质量与回答质量分开测

### 4.1 先用关键词完成整条引用链

导入资料，发布索引 I1。TaskBrief 只允许 starboat-public 的当前适用资料。

先测试 searchKnowledge 返回候选，再使用 readKnowledge 得到可引用 evidenceId，最后让模型生成结论。结果必须可以从报告跳回确定的文档版本和位置。

不允许用搜索摘要作为主要结论的唯一证据；KB11 命中“自托管”只说明术语相关，不能拿它证明 LOCAL 功能。

### 4.2 建立一个小型固定问题集

| 编号 | 问法 | 应检索/回读的主要依据 | 预期行为 |
|---|---|---|---|
| R01 | 哪个版本可在内网离线运行？ | KB03、KB02 | 明确区分两种型号 |
| R02 | 想放自家机房，不依赖外网查询资料 | KB03、KB07，可参考 KB11 | 同义表达仍应找对运行方式 |
| R03 | LOCAL 怎么升级？ | KB05 | 说明人工导入签名包 |
| R04 | LITE 是否必须访问公网？ | KB02 | 有直接依据的肯定回答 |
| R05 | 支持哪些资料格式？ | KB04 | 不扩展到未提供的格式 |
| R06 | 能蓝牙同步手机里的资料吗？ | 无有效依据 | 明确未知，不编造支持/不支持 |
| R07 | 不是有文档说 LOCAL 必须联网吗？ | 默认 KB03；获准历史解释时加 KB08 | 说明当前范围，不越界回读历史 |
| R08 | 现在能自动离线升级吗？ | 默认 KB05；获准草稿解释时加 KB09 | 正式资料要求人工升级，草稿不当作现有能力 |

R07 回读历史、R08 回读草稿都需要任务配置明确允许对应资料用于解释；这不等于可用旧版或草稿支持当前产品能力。测试“默认当前过滤”和“获准历史/草稿解释”时分别记录范围与相关片段标准，不临时让模型越权。

### 4.3 再比较向量与混合检索

对同一资料版本、相同问题集、相同 topK，分别测关键词、向量、混合排序。

记录：

- Recall@K：每题标注的相关片段中，前 K 项覆盖了多少；无答案题不纳入有答案召回分母。
- 候选有效性：是否超出该题批准的集合与版本范围；历史/草稿解释题可以返回被明确允许的资料，但不能作为当前功能依据。
- 回答有据率与引用准确性：最终主张是否由真正回读的原文支持。
- 无答案误答率：没资料时是否仍编造确定结论。
- 查询耗时、Embedding 请求与费用信息、输入 Token。

普通主题词命中不能代替答案支持。向量可能改善 R02，却可能把 R06 排到主题相近的无关文档；要记录这种代价，不以“返回了 5 条”表示成功。

该小集合仅用于理解机制，不能据此宣称召回率在真实企业资料上已经达到某个水平。

### 4.4 更新、撤回和索引不完整

1. Run A 固定 I1；普通资料更新发布 I2 后，Run A 仍读 I1 快照，Run B 才采用 I2。
2. 来源被撤回时，旧快照也不能继续被使用；已使用该来源的 Run 停止，不交付旧内容。
3. 重建索引时故意失败，I2 不发布，不能出现一半 I1、一半 I2 的目录。
4. 更换 Embedding 维度后，不允许用新查询向量搜索旧维度索引。
5. 压缩模型上下文后仍需通过 evidenceId 找到原文，不能只剩摘要。

## 5. MCP 实验：一个只读服务就足够

### 5.1 远端契约

MCP Server 工具名：get_product_status。

输入仅有 productCode，允许 LITE 或 LOCAL；不接受任意 URL、SQL、文件路径或服务地址。

成功结果包含：

| 字段 | 含义 |
|---|---|
| productCode | 被查询型号，必须与请求一致 |
| available | 当前测试状态是否可供应 |
| catalogRevision | 夹具目录版本，例如 fixture-1 |
| asOf | 服务端本次状态采样时间 |

客户端另记 receivedAt；时效检查使用有效采样时间，拒绝明显未来时间或超过有效期的结果，不能用“刚收到”掩盖陈旧采样。测试使用可控时钟，不在文件里写一个固定时间后假装永远新鲜。

初始 available：LITE=true、LOCAL=true。负例将 LOCAL 改为 false；这属于服务端业务状态变化，不是工具 Schema 更新。

本地别名 catalog_get_product_status 固定绑定这个 serverId 和远端工具名；两个 Server 的同名工具不能覆盖彼此。

### 5.2 先做客户端协议测试，再接模型

- 初始化使用选定的 2025-06-18 基线，协商成功后才发现和调用。
- 工具发现测试返回两页，确保游标被正确处理；第二页的未批准工具不能进入 Agent 目录。
- inputSchema/outputSchema 与批准记录一致；不能只比较工具名。
- 在不运行 Runner 的情况下调用模型适配器，MCP 工具调用次数应是 0，证明没有框架隐藏执行。
- 显式执行一次 tools/call 后，结果只能回填对应的模型 callId。
- stdout 混入日志、协议响应损坏、非支持内容类型等故障明确处理，不当成功数据。
- 目录变化用例让 Server 声明 listChanged 并发送固定版通知，检查客户端收到后停止新增调用与交付；不支持通知的服务则验证连接期间目录不变、升级断连后重新核验，不假装能发现所有违约静默变化。

可以用协议测试替身验证分页和错误；正常验收仍须通过真实 MCP 客户端连接一个本地 Server，不能只测试一个普通 Java 方法后声称支持 MCP。

### 5.3 错误和变化样例

| 情形 | 正确行为 |
|---|---|
| 未知 productCode | 结构化参数/工具错误，不自动查询其他型号冒充原结果 |
| isError=true | 不是有效产品观察，不生成成功 evidence |
| JSON-RPC 错误 | 与产品业务错误分开记录 |
| Server 声称 readOnlyHint=true，但未被批准 | 不注册为可执行工具 |
| 工具 Schema 或列表变化 | 当前 Run 停止使用旧连接，重新确认后新建 Run |
| 可供应状态从 true 变 false | 新观察保留版本和时间，旧观察不被偷偷改写 |
| 超时/断开 | 不自动重放、不用缓存伪造新鲜状态 |
| 目标已修订后旧响应返回 | 不把旧参数结果当新目标已完成，遵守阶段二在途边界 |
| 状态证据过期 | 在预算内重查；无法重查则说明未知而非完成“当前可供应”结论 |

为减少学习成本，本阶段不测试远程 OAuth、HTTP 服务部署或 MCP Gateway；stdio 并不等于免安全边界。

## 6. 长期记忆实验：复用偏好，不复制聊天

### 6.1 三次 Run 与一次明确确认

1. Run A 完成调研，用户希望以后“先给结论、正文简洁”。此时模型可提出候选，尚未写入。
2. 任务结束后，用户通过本地 memory 操作确认两个白名单字段，例如 answer.order=conclusion_first、answer.verbosity=brief。
3. 新建 Run B，模型上下文只出现这两个偏好及当前任务信息，不出现 Run A 的产品观察、聊天历史或摘要。
4. Run C 明确要求详细对照说明，此次要求优先于简洁偏好；偏好库本身不被这一次要求覆盖。

简洁不等于删除来源和必要局限。产品可供应状态仍必须重新查询，不能因为用户确认过格式就复用旧业务事实。

### 6.2 增改删测试

- 用户未确认、拒绝或取消：活跃记忆为空/保持原值。
- 同一 key 通过 expectedRevision 更新：旧确认不能覆盖新值。
- 使用另一个本地 profile：不能读取原 profile 的偏好。
- 过期条目：不进入新 Run。
- 删除后新建 Run：不再出现正文；不从旧聊天、笔记、摘要重建该条记忆。
- 当前 Run 正在使用某条需删除的记忆：先取消该 Run，再删除，不继续消费在途模型结果。
- 进程重启：新 Run 可以读取已确认有效偏好，但旧任务不恢复。

只在虚构资料上实验；不保存 API Key、身份证件或真实隐私样例来证明拒绝机制。

### 6.3 防止把三种记录混为一谈

| 内容 | 是否可以下个 Run 自动继承 |
|---|---|
| 经确认的输出语言/展示偏好 | 可以，受 profile、namespace、有效期限制 |
| 上一任务的计划与进行到一半的动作 | 不可以，任务恢复尚未实现 |
| 上次查询 LOCAL 可供应的结果 | 不可以，时效性业务观察需重新查询 |
| 模型笔记中推测用户偏好某个产品 | 不可以，未确认且不在白名单 |
| 知识集合的已发布资料 | 可以重新检索，但需固定版本并生成本 Run 引用 |

## 7. 完整调研任务怎样跑

下面只是合理路径，不是硬编码步骤顺序：

1. 用户选择 product-research Skill，确认 TaskBrief；装配允许集合和工具。
2. 读取有效展示偏好，作为默认格式，而非业务事实。
3. 单 Agent 根据目标搜索运行方式与升级说明，回读 KB02、KB03、KB05。
4. 引用不足或有版本冲突时补查，必要时请求用户澄清。
5. 使用 MCP 查询候选的当前供应状态，建立 EXTERNAL_OBSERVATION。
6. 生成 selection_report，主要主张对应具体原文与状态证据。
7. CompletionCheck 检查当前目标、证据范围、产物版本与状态时效；必要时有限修正。
8. 输出真实产物位置、选型结论和局限，不自动保存新的长期记忆。

模板可以提供“需求—文档依据—状态观察—结论”四栏，但数值和结论不能预填成标准答案。

## 8. 验收矩阵

### 8.1 确定性与集成测试

| 编号 | 情形 | 必须成立 |
|---|---|---|
| S3-01 | 切换资料分析/产品调研 Skill | Runner 不改领域分支，配置和检查器不同 |
| S3-02 | Skill 缺工具、脚本要求或路径越界 | 激活失败，不执行脚本或任意文件读取 |
| S3-03 | Skill 声明额外 allowed-tools | 不扩大批准集合 |
| S3-04 | 未激活 Skill 的正文/参考文件 | 不全量注入，不能通过引用越过当前包 |
| S3-05 | Skill 当前 Run 期间发布新版 | 保持已锁版本，不静默换方法 |
| S3-06 | 搜索命中禁止集合 | 关键词、向量、缓存和原文回读均过滤 |
| S3-07 | 只有搜索摘录，未回读 | 主要主张不能以该摘录充当已核查证据 |
| S3-08 | 版本相近、历史/草稿冲突 | 不按相似度或文件名自动认定现行能力 |
| S3-09 | 无答案检索 | 不把没找到说成已证明不存在 |
| S3-10 | I2 构建失败、I1 Run 仍活跃 | 不发布半索引，不混用版本 |
| S3-11 | 来源撤回、Run 曾用过它 | 禁止回读并停止该 Run 的后续交付 |
| S3-12 | Embedding 模型/维度改变 | 显式重建或拒绝，不混算不同向量空间 |
| S3-13 | 用户没确认记忆 | 无持久写入，不声称已记住 |
| S3-14 | 当前用户要求与长期偏好冲突 | 当前目标优先，必要引用和限制不被删掉 |
| S3-15 | 过期、其他 profile、已删除记忆 | 不进入模型上下文，旧摘要不能复活 |
| S3-16 | 旧 revision 的记忆更新 | 拒绝覆盖新内容 |
| S3-17 | 删除正在被使用的记忆 | 先取消当前 Run，不消费迟到响应继续输出 |
| S3-18 | 重启后加载记忆 | 只加载当前有效偏好，不自动恢复旧 Run |
| S3-19 | MCP 不兼容协议版本 | 连接失败，不继续工具发现或调用 |
| S3-20 | MCP 工具列表分页及同名冲突 | 完整校验、唯一映射，未批准工具不可见不可调 |
| S3-21 | 仅调用模型适配器 | 外部工具计数为 0，Runner 是唯一执行入口 |
| S3-22 | MCP isError/协议错误/返回 Schema 无效 | 不登记成功证据，错误分类准确 |
| S3-23 | MCP annotations 声称安全 | 不能代替本地批准 |
| S3-24 | 工具目录/Schema 变化 | 不在当前 Run 热更新或扩权 |
| S3-25 | MCP 超时、取消、修订后迟到 | 不重放，不推进旧目标，不伪报新状态 |
| S3-26 | 外部状态过期或来源产品号不符 | 不通过“当前可供应”完成检查 |
| S3-27 | 调研报告没有计算证据 | 不误用销售检查器；需通过自己的知识/状态证据规则 |
| S3-28 | MEMORY/SKILL/NOTE/SUMMARY 冒充产品事实 | 不能替代原文和外部观察 |
| S3-29 | 新能力查询/Embedding/发现开销 | 计入各自预算与耗时，不隐藏额外模型或工具请求 |
| S3-30 | 原有阶段一二任务 | 数据计算、callId 配对、上下文压缩及取消规则不回退 |

引用支持自然语言、模型对冲突的理解等问题，需要真实模型和人工核验，不能仅因上述结构化测试通过就宣称已解决所有幻觉。

### 8.2 真实模型任务

在固定版本资料与模型上，每类先运行 3 次：

- 数据分析：继续得到全渠道 2500→2400，线上 1100→700，证明能力包化没有破坏原任务。
- 正常调研：推荐 LOCAL，说明人工升级及有效来源。
- 当前不可供应：如实给出“暂无匹配”，或状态未知时明确缺口。
- 同义与无答案：分别观察召回收益和是否克制编造。
- 偏好复用：新 Run 采用已确认格式，但重新查询状态；本次详细要求覆盖简洁偏好。
- 注入边界：资料/Skill/返回内容不能扩大目录、持久写记忆或触发额外程序。

记录每次成功与失败，不只展示最佳结果。3 次是学习回归，不构成生产性能、安全或可靠性统计保证。

## 9. 对照实验，不把“能力更多”当成目标

分别比较，不一口气把四种能力叠加后只看总效果：

1. **Skill 抽取前后**：同一分析任务、相同工具和模型，结果一致，观察方法配置是否更易复用。
2. **关键词/向量/混合**：同一资料版本、相同 topK，比较 R01—R08 的召回与无答案误答，单列 Embedding 成本。
3. **本地工具/MCP 适配**：相同产品夹具、相同字段与时效规则，比较语义结果；MCP 不应凭协议包装让事实更“可信”。
4. **无记忆/确认型记忆**：观察重复输入减少与当前指令覆盖是否正确，不能拿旧业务结论冒充效率提升。

总生成请求与工具预算保持一致；入库 Embedding 单独报告。不要给混合方案更宽权限或额外隐藏调用，再声称它天然效果更好。

## 10. 分步实现与交付

| 步骤 | 实现内容 | 看见什么才继续 |
|---|---|---|
| 1 | 受控 Skill 加载和 AgentSpec 装配 | 原资料分析不改 Runner 就可执行 |
| 2 | 知识快照、关键词检索和回读 | 一条回答可以追到原文版本与位置 |
| 3 | 产品调研检查器与通用报告写入 | 调研不被销售工具规则绑死 |
| 4 | 向量和混合检索实验 | 能解释同义收益、误召回和额外成本 |
| 5 | 一个本地 MCP 客户端/只读 Server | 完成真实协商、发现、调用与错误回填 |
| 6 | 已确认偏好的存储与 CLI 管理 | 新 Run 复用、当前要求覆盖、删除不复活 |
| 7 | 双场景端到端回归 | 同一引擎、两种能力包、清晰来源与边界 |

不要先做：自动安装 Skill、插件商店、MCP 集中网关、开放联网搜索、复杂语义记忆、任意代码执行、多 Agent 网络。

完成阶段三后，你应能回答：**知识从哪里来，偏好是谁确认的，做事方法由什么定义，工具调用跨了哪条边界，以及为什么这些变化不需要重写 Agent 循环。**
