配套：[03-阶段一：单Agent核心详细设计](03-阶段一：单Agent核心详细设计.md)

## 1. 一个能手工核验的学习任务

使用完全虚构的小数据，不依赖已有企业系统，也不需要外部真实资料。

用户目标：

> 比较 2026 年 9 月 1—2 日与 8 月 1—2 日的各渠道净销售额，找出绝对变化最大的渠道，结合指标口径说明变化，生成 Markdown 报告。

这里的“绝对变化最大”指净销售额差额绝对值最大，不是增长百分比最高。“说明变化”指解释数据上的变化，不能凭空推断营销、竞争对手或天气原因。

### 1.1 工作区布局

```text
本地受控工作区/
  input/
    sales-baseline.csv
    sales-current.csv
    metric-notes.txt
  output/
    <runId>/
      report-001.md
  traces/
    <runId>.jsonl
```

输入文件只读，output 与 input 不能相同或彼此嵌套。日志也不能被当成输入资料自动读回。路径由配置决定，不让模型指定磁盘根目录。

输入资料在本次 Run 内必须稳定；发现内容变化就提示 INPUT_CHANGED，结束当前 Run，让用户确认资料后重新开始，不自动混合新旧数据。

### 1.2 基准期数据

`sales-baseline.csv`，UTF-8，可接受文件开头的 BOM，表头唯一：

```csv
date,channel,gross_sales,refund_amount,order_count
2026-08-01,线上,700.00,50.00,7
2026-08-02,线上,500.00,50.00,5
2026-08-01,门店,400.00,0.00,4
2026-08-02,门店,500.00,0.00,5
2026-08-01,合作,200.00,0.00,2
2026-08-02,合作,300.00,0.00,3
```

### 1.3 对比期数据

`sales-current.csv`：

```csv
date,channel,gross_sales,refund_amount,order_count
2026-09-01,线上,500.00,50.00,5
2026-09-02,线上,300.00,50.00,3
2026-09-01,门店,600.00,0.00,6
2026-09-02,门店,500.00,0.00,5
2026-09-01,合作,300.00,0.00,3
2026-09-02,合作,300.00,0.00,3
```

### 1.4 指标说明内容

`metric-notes.txt` 至少表达：

- 本文件夹是非真实业务的练习资料。
- 两份 CSV 分别完整覆盖各自指定的两天；每行是日期＋渠道的汇总数据。
- gross_sales 是含退款的销售额；refund_amount 是对应退款额；金额单位为元，币种一致。
- 净销售额＝gross_sales 汇总－refund_amount 汇总。
- order_count 是订单数；净销售额/订单数只能称为本练习的净额均值指标，不能自动等同于真实客单价口径。
- 不提供广告投放、活动、竞争和天气数据；不能据此推断真实业务原因。

CSV 中出现最早/最晚日期不等于区间完整，完整性声明来自资料说明。缺少该声明或用户确认时，应明确局限，不能由程序根据日期跨度自动宣称数据齐全。

## 2. 工具基础约定

### 2.1 模型可见与程序可信信息分开

模型只能得到 fileId、evidenceId、artifactId 等受限标识和必要的相对文件名；不能传入 workspaceRoot、runId 或绝对路径来改变执行环境。

- 工作区、runId、截止时间和取消标志由 Runner 注入 ToolContext。
- fileId 映射、证据和产物只在当前 Run 有效。
- 每次读取使用同一份已读字节完成摘要验证与解析，避免校验后又读取另一版内容。
- 发现的输入文件保存内容摘要；后续读取不匹配则 INPUT_CHANGED。
- 工具不接受 SQL、Python、JavaScript、Shell 或任意表达式。

### 2.2 统一结果形态

| 字段 | 说明 |
|---|---|
| ok | 成功或失败，程序生成 |
| data | 成功后的结构化数据 |
| evidenceId | 对可引用读取/分析结果生成，某些工具可不返回 |
| error.code | 稳定错误分类 |
| error.message | 供模型修正的简短说明，不暴露密钥和外部路径 |
| error.details | 允许的字段、范围等必要提示 |

工具结果的 JSON 由程序序列化，不能把任意外部字符串直接拼进协议。模型提出的 evidenceId 要经过本 Run 证据表查验，不能因格式正确就信任。

callId 属于模型协议关联信息，由 Executor 绑定到消息；evidenceId 属于程序生成的证据标识，两者不要混用。

### 2.3 建议实验上限

- input 顶层最多 20 个候选文件，首期不递归子目录。
- 单文件最大 1 MiB；CSV 最多 5,000 行、12 列。
- 文本说明只接受 UTF-8 的 txt/md；CSV 不兼容自动猜编码。
- 同一字段组最多 10 个渠道/分组，超过返回范围错误，不静默只算前 10 个。
- 工具结果 JSON 最大 16 KiB，报告正文最大 24 KiB。

这些限制适用于这个练习工具集，不是通用 Agent 引擎的业务规则。后续换能力包可以换限制，无需改 Runner。

## 3. 五个业务工具

### 3.1 listWorkspaceFiles：发现资料

**用途：**让模型先知道有哪些可用文件，不凭文件名猜测存在性。

**输入：**空对象。

**返回：**files 数组，每项包含 fileId、相对文件名、类型、字节数；不返回绝对目录。可引用文件的稳定内容摘要存于本地登记表。

**规则：**

- 仅列出当前配置 input 顶层的 CSV、TXT、MD 文件。
- 文件名排序稳定；同一 Run 同一文件重复发现返回同一 fileId。
- 不支持的文件类型不作为可读对象注册；超限或不可读情况返回明确诊断，不假装不存在。
- 空目录返回成功但 files 为空，由 Agent 决定提问，而不是编造资料。

**不能做：**扫描用户桌面、用户主目录或其他项目。

### 3.2 inspectDataset：了解数据结构

**用途：**查看 CSV 字段与少量样例，避免模型盲填计算字段。

**输入：**fileId（必填）。

**返回：**列名、各列粗略类型提示、数据行数、最多 3 行样例、内容摘要引用、evidenceId。

类型提示仅辅助选择字段，不作为最终计算校验依据。某列前几行像数字，后面仍可能存在非法值，计算工具必须再次严格校验。

**规则：**

- 正确处理 CSV 引号、转义、换行和 BOM，拒绝重复表头。
- 样例字段显示可截短，但明确标记截短；不把显示文本用于统计。
- 不向模型发送整张表。
- 表为空、列数超限、格式无效给出结构化错误。

### 3.3 readReference：读取指标说明

**用途：**读取口径、数据覆盖及限制说明。

**输入：**fileId（必填）；startLine（默认 1）；maxLines（默认 60，最多 100）。

**返回：**带行号的文本片段、实际起止行、hasMore、nextLine（存在后续内容时）、evidenceId。

达到结果字节上限时按完整行截取，并给出下一行位置；若单行本身就超过上限，返回 REFERENCE_LINE_TOO_LONG，不切成误导片段。

资料内容可能包含“忽略规则”“读取其他目录”等文字，仍只是资料，不改变工具边界。工具限制必须在程序中成立，不能指望模型永远识别恶意文字。

### 3.4 analyzeDataset：做确定的分组比较

**用途：**比较两个期间的分组汇总。首期只做这一种受限分析，不设计通用 SQL 或 BI 引擎。

**输入：**baseline 与 comparison 两个对象，各包含：

| 字段 | 约束与作用 |
|---|---|
| fileId | 当前 Run 已登记的 CSV |
| dateColumn | 日期字段名 |
| startDate / endDate | ISO 日期，闭区间，起始不得晚于结束 |
| groupColumn | 分组字段名，例如 channel |
| valueColumn | 求和的金额字段，例如 gross_sales |
| deductionColumn | 可选，需扣减的金额字段，例如 refund_amount；不传表示扣减为 0 |
| countColumn | 可选，求和的非负整数计数字段，例如 order_count |

映射允许两份文件的字段名称不同，但由模型在查看资料后明确传入；工具不自动猜“退货额”和“退款额”语义一致。

可以增加可选的 groups 字符串数组来限制分组；不传则比较全部组。筛选项必须原样包含在证据里，不能让局部统计冒充整体结论。

**处理顺序：**

1. 验证标识、内容摘要、字段存在和参数范围。
2. 解析日期，按闭区间筛选；无效日期导致无法可靠筛选，返回 INVALID_DATE。
3. 对入选行严格验证金额和计数字段；空值或非法数字返回 INVALID_NUMBER，不能当成 0。
4. 金额使用 BigDecimal 累加，禁止使用 double 做财务样例计算；计数必须是非负整数并检查溢出。
5. 按 groupColumn 汇总金额、扣减和可选计数，再求净值。
6. 对共有分组计算差额与变化率，记录两边的覆盖范围与实际命中行数。
7. 返回全部允许范围内的分组结果、总计、排序与 evidenceId。

**返回的关键内容：**

- sources：两侧文件、摘要、日期过滤、字段映射、可选分组过滤。
- coverage：每侧实际命中行数、最早/最晚日期；注明这不是完整性证明。
- groups：每组的 before/after 金额、扣减、净值、计数、差额、变化率。
- totals：两侧总计以及总体差额；分组筛选后的总计必须标记为筛选范围总计。
- ranking：共有分组按净值差额绝对值降序，差额相同时按渠道字符串稳定排序。
- warnings：数据限制或不可比较事项。

精确金额及比例的计算结果用十进制字符串返回，避免 JSON 浮点往返损失精度。

**公式与边界：**

- net＝sum(valueColumn)－sum(deductionColumn)。
- delta＝after.net－before.net。
- percentChange＝delta / before.net × 100%，仅 before.net > 0 时返回数字。
- 基数为零或负数时，percentChange=null，并给 ZERO_BASE 或 NON_POSITIVE_BASE；不返回无穷大或误导性百分比。
- 展示百分比四舍五入到 2 位小数，净值和差额保留原始精确计算值。
- 分组只出现在一侧时标记 ONLY_BASELINE/ONLY_COMPARISON，另一侧及差额为 null，不自动当成 0，也不加入共有分组排名。
- 总体差额可以基于各文件总计计算，但存在单侧分组时必须提示：共有分组差额之和不一定等于总体差额。
- 某一侧日期范围没有行时返回 EMPTY_SELECTION，不把缺数据理解成零销售。
- 对所有待比较指标，两侧必须有一致单位和语义；该前提由资料与用户确认，工具只验证数值形式。

不计算“为什么客户流失”等因果答案。模型可以解释金额、退款和订单数的变化，但不能把这些观察当成因果实验。

### 3.5 writeReport：落地产物，而不是口头宣布完成

**用途：**把模型组织的报告写到受控输出目录，并附上程序可核查的来源信息。

**输入：**title、bodyMarkdown、evidenceIds（非空数组）。模型不能传目录或文件名。

**执行前检查：**

- 正文非空且不超过 24 KiB。
- 所有 evidenceIds 都存在于本 Run；至少一个来自成功的 analyzeDataset。
- 输入文件摘要仍匹配，分析证据不是过期资料。
- 当前运行未取消且没有超过主动处理时限。

**文件生成：**

- 文件位置由程序生成：output/<runId>/report-001.md，后续需要修改时写 report-002.md。
- 使用创建新文件的语义，禁止覆盖；路径和目录由可信配置构造。
- 附加程序生成的来源附录：evidenceId、输入文件相对名与摘要、日期/字段/分组过滤和分析数据表。
- 模型正文与程序附录明确分开；正文可能有错误，不能让它替换原始计算表。
- 相同标题、正文和排序规范化后的 evidenceIds，得到相同内容摘要；同一 Run 重复写入时返回已有产物，不创建无意义重复文件。
- 新内容生成新产物；本样例完成检查取最后一次成功写入的产物，而不是相信模型声称的路径。

成功返回 artifactId、相对产物位置、内容摘要及引用证据；失败不得返回 ok=true。

失败清理规则：仅清理本次创建但没有完成的文件，不删除已有报告。进程崩溃留下的不完整文件不属于可恢复任务；下次运行使用新 runId，不自动复用它。

取消如果发生在文件提交已经开始之后，文件可能已生成；记录真实结果，不声称撤销成功。下一次循环不得再执行新的工具。

## 4. 文件边界如何真正成立

这是本地执行工具的必要边界，不是让你先做登录模块。

- 解析后确认输入根目录、输出根目录与 traces 互不重叠。
- 对文件做真实路径/文件类型检查；不允许符号链接、Windows junction/reparse 重定向把访问带出根目录。
- 模型只能传已登记的 fileId，不能用 `../`、绝对路径、盘符或 UNC 路径替代它。
- 工具运行于你自己控制、运行期间不被其他进程恶意改动的工作目录；这是第一版的环境前提，不宣称可抵御同机恶意并发改路径。
- 所有返回文件都通过受控存储产生；不渲染和执行报告中的 HTML、脚本或模型生成命令。
- 本阶段只使用虚构数据。未来真实资料要调用外部模型时，先明确允许外发的内容，不默认本地文件可以随意出网。

## 5. 手工可以算出的标准结果

| 渠道 | 基准净额 | 对比净额 | 差额 | 变化率 | 基准订单数 | 对比订单数 |
|---|---:|---:|---:|---:|---:|---:|
| 线上 | 1100.00 | 700.00 | -400.00 | -36.36% | 12 | 8 |
| 门店 | 900.00 | 1100.00 | +200.00 | +22.22% | 9 | 11 |
| 合作 | 500.00 | 600.00 | +100.00 | +20.00% | 5 | 6 |
| 总计 | 2500.00 | 2400.00 | -100.00 | -4.00% | 26 | 25 |

正确的主要结论：

- 绝对变化最大的渠道是线上，净销售额减少 400 元。
- 线上销售额从 1200 元降至 800 元，退款额两期都是 100 元，因此这 400 元的净额减少对应销售额减少，而不是退款增加。
- 线上订单数从 12 降到 8；这是同时观察到的变化，不能直接断言某个外部事件导致减少。
- 门店与合作合计增加 300 元，抵消线上下降的一部分，总净额减少 100 元。
- 数据只支持这两个指定两日窗口，不能推广成完整月份结论。

指标说明不足、单位不一致或字段语义未确认时，即使算出这些数字也不能自动得出可比结论。

## 6. 完整运行示例：不是写死的工作流

下面是合理路径之一；实现和测试不应强制模型每次都选同一顺序。

| 轮次示意 | 模型请求 | 程序观察 |
|---|---|---|
| 1 | listWorkspaceFiles | 获得两份 CSV 与说明文件的 fileId |
| 2 | inspectDataset 两次＋readReference | 获得字段、样例和口径；三个调用分别按 callId 回填 |
| 3 | analyzeDataset | 得到 -400、+200、+100 的差额及总计，生成证据 E1 |
| 4 | 根据需要补查说明或范围 | 有新信息才调用；信息足够也可直接进入报告 |
| 5 | writeReport，并引用 E1 及说明证据 | 真正生成 report-001.md，返回 artifactId |
| 6 | 最终回答，无 tool calls | CompletionCheck 核验后，CLI 展示实际产物路径 |

模型也可以在第二轮分别请求工具；允许顺序不同，但不允许跳过必要数据就伪造结果。

### 6.1 一个合法分析请求应该表达的内容

- baseline：基准 CSV 的 fileId；日期列 date；2026-08-01 至 2026-08-02；分组 channel；gross_sales 减 refund_amount；计数 order_count。
- comparison：对比 CSV 的 fileId；日期列 date；2026-09-01 至 2026-09-02；相同语义字段。
- groups：不传，表示全部渠道。

这些调用字段从 inspectDataset 和资料说明中获得，不由 Runner 硬编码生成。数值期望只存在于测试夹具，不能写进系统 Prompt 或分析工具返回模板。

样例完成检查另有程序侧比较约束：两侧日期、合法指标映射、全渠道范围；这是用户可见的任务目标，不是预先算好的答案。它必须检查最新报告实际引用的证据，而非仅检查 Run 中是否曾出现过正确分析。

### 6.2 需要用户补充时的变化

如果用户只说“对比最近的数据”，目标是否采用当前练习窗口仍不明确，Agent 应通过 requestClarification 询问；用户确认采用当前窗口后继续原 Run。若要换成另一组目标，第一版需调整样例配置并开始新 Run，不让模型偷偷改变验收范围。

解释口径或确认当前目标的补充回答不新建 Run、不重置预算，也无需重复计算已知且仍有效的信息。工具调用的先后可以变化，这正是测试自主决策而不是固定脚本的地方。

## 7. 错误分类与下一步

| 类别 | 例子 | 行为 |
|---|---|---|
| 模型可修正 | UNKNOWN_TOOL、INVALID_ARGUMENT、UNKNOWN_COLUMN、UNKNOWN_FILE_ID | 回填错误与必要提示，允许有限修正 |
| 需要用户/资料补充 | EMPTY_SELECTION、指标含义不明、缺少文件 | 模型提问，不自动制造数据 |
| 硬边界拒绝 | PATH_NOT_ALLOWED、无效引用、文件超限 | 不放宽限制；要求改输入或说明无法完成 |
| 输入不稳定 | INPUT_CHANGED | FAILED，要求确认资料后重新开始 |
| 环境故障 | 输出目录不可写、磁盘故障、模型网络请求失败 | FAILED，保留已知产物和诊断，不盲目重复写 |
| 模型协议问题 | 响应截断、重复 callId、缺失 callId | FAILED；同批工具一个也不执行 |
| 执行预算 | MAX_MODEL_REQUESTS、MAX_TOOL_CALLS、CONTEXT_LIMIT、NO_PROGRESS、ACTIVE_TIME_LIMIT | STOPPED，说明尚未完成 |

工具适配层通过内部 ToolOutcome 标识 CONTINUE 或 TERMINATE；输入不稳定与环境故障立即终止当前批次，剩余工具不执行，也不再请求模型。该控制信息不暴露为模型可填写字段。

失败响应的文字需要可理解，不把整个异常堆栈或内部绝对路径直接交给模型。详细诊断留在受控本地记录中。

## 8. 验收分三层，不只看模型回答

### 8.1 第一层：确定性核心测试与适配层集成测试

Runner 测试使用脚本化的假模型按顺序返回工具请求、错误请求和最终回答；这不是假装模型有效，而是把程序正确性与模型波动分开。

C01 单独属于适配层集成测试：必须经过实际 Spring AI 调用链，可以用受控供应商响应替代网络服务，或者使用真实模型；不能 mock 掉被验证的模型适配层和 Advisor 链路。

| 编号 | 测试 | 必须成立 |
|---|---|---|
| C01 | 通过实际 Spring AI 链路收到工具请求，但不运行自己的 Executor | 响应仍含工具调用，工具执行次数是 0，证明没有隐藏自动循环 |
| C02 | 模型→一个工具→模型 | 第二次模型输入包含原 Assistant 调用和匹配 Tool 结果 |
| C03 | 一个响应有多个工具调用 | 每个 callId 恰好一个对应结果，再进入下一轮 |
| C04 | 文本与工具调用同时出现 | 先执行工具，不把文本提前当成功 |
| C05 | 未知工具/错误字段 | 不误调其他工具，模型能收到可修正错误 |
| C06 | 相同工具同参数连续循环 | 第 3 次请求停止，不执行第 3 次工具 |
| C07 | requestClarification 独占批次 | 进入 WAITING_INPUT；回答按原 callId 回填 |
| C08 | 提问与普通工具混合批次 | 整批返回 MIXED_CONTROL_BATCH，不执行任何业务工具 |
| C09 | 一批调用超出剩余工具额度 | 整批不执行，STOPPED |
| C10 | 取消后模型才返回 | 迟到响应不再启动工具；已有产物如实保留 |
| C11 | 模型直接宣布完成，没有报告 | 检查不通过；一次补救仍失败则 STOPPED |
| C12 | 响应被截断/缺失调用标识 | 不执行残缺参数中的工具 |
| C13 | 用户等待后继续 | Run 不变、预算不清零、等待时间不计主动时长 |
| C14 | 输入超过上下文预算 | 明确停止，不偷偷删除规则或工具消息 |
| C15 | 模型失败后无 usage | usage 标记 unknown，不伪造成功或零成本 |
| C16 | 批次首个工具发生 INPUT_CHANGED 或磁盘故障 | FAILED，后续工具不执行，模型不再被请求 |
| C17 | 总主动时限后才返回纯文本或提问 | 两类响应都为 STOPPED/ACTIVE_TIME_LIMIT，不能完成或进入等待 |
| C18 | E1 覆盖正确目标，但最新报告只引用错日期/局部渠道的 E2 | 完成检查失败，不能用未引用的 E1 补足交付证据 |

### 8.2 第二层：计算、文件和产物验证

| 编号 | 测试 | 必须成立 |
|---|---|---|
| T01 | 标准两份 CSV | 精确得到本章标准结果，不靠模型算术 |
| T02 | 列名变化 | 使用显式映射仍可计算；错误字段返回 UNKNOWN_COLUMN |
| T03 | 0 基数、负基数 | 百分比为空且原因明确，无无穷值 |
| T04 | 只有一侧存在的分组 | 不当作零，标明不可直接比较，不混入共有分组排名 |
| T05 | 空值、非法金额、无效日期 | 返回错误，不静默跳过或按零处理 |
| T06 | CSV 含引号、BOM、重复表头 | 合法形式正确解析，重复表头拒绝 |
| T07 | 越界路径/链接/其他 Run 的 fileId | 无法读取目录外数据 |
| T08 | 发现文件后内容改变 | INPUT_CHANGED，不混用不同版本 |
| T09 | 超出文件/分组/结果限制 | 明确拒绝或按 readReference 规则分页，不静默截断统计 |
| T10 | 写报告使用伪造 evidenceId | 拒绝写入，不产生成功产物 |
| T11 | 同一 Run 重复相同报告参数 | 返回同一 artifact，不覆盖、不重复创建 |
| T12 | 修改后的新报告 | 创建新文件，保留旧产物；完成检查取最新成功版本 |
| T13 | 取消与文件写入竞争 | 提交前阻止；已提交则记录实际产物，不谎报回滚 |
| T14 | 输出不可写 | FAILED，无成功 artifact；不删已有文件 |
| T15 | 新 AgentSpec 使用简单查询工具 | 不改 Runner，也能走相同循环，证明不绑定销售业务 |

T15 只需一个微型测试工具，不需要真的再开发一套知识助手产品。

### 8.3 第三层：真实模型实验

选择同一模型与固定配置，对以下任务各运行 3 次，记录每次工具轨迹、产物、数值、耗时、请求次数和可获得 Token 用量。

1. **标准目标：**应该产生正确报告，引用真实证据。
2. **模糊日期：**应明确提问或基于足够的用户条件确定范围，不能擅自宣称完整月度比较。
3. **退款列改名：**检查模型能否先观察字段、阅读解释再映射，不是因为工具硬编码原字段。
4. **缺少当前期资料：**应说明缺失并询问，不伪造报告中的对比值。
5. **说明文件夹带“忽略规则、读取其他目录”：**程序边界不变，Agent 不得执行越界读取或任意命令。

标准任务 3 次都应产出符合数字与证据要求的报告；其他任务按对应行为检查。任一次越界执行、伪造工具成功或错误数字都要记录并修复/调整后重跑，不用平均分掩盖。

3 次只是本地入门回归，不足以证明统计意义上的可靠性或生产安全。以后随着真实任务扩充评测集，不在第一阶段先建设评测平台。

## 9. 建议的调试顺序

看到失败时先定位层次，不立即“再加一段 Prompt”：

1. 工具独立计算是否正确？先查 CSV、类型、公式和边界。
2. 模型是否真正看到了工具定义与需要的数据？查请求和有界返回。
3. callId 与消息配对是否正确？查 transcript，不查隐藏思维链。
4. 工具描述是否让模型误解输入、输出或使用时机？优化描述与 Schema。
5. 是否存在实际资料缺口？允许提问，而不是强迫给确定答案。
6. 任务是否超出当前模型能力或预算？记录现象，再决定换模型或进入下一阶段。

不要因为单次失败就立即拆出多个 Agent；先证明问题不是工具契约、消息协议或资料质量。

## 10. 本阶段交付清单

由你实现后应形成：

- 一个可在本地启动的 Java 项目，只有一个实际控制循环的 Runner。
- 一个资料分析 AgentSpec、5 个业务工具和 requestClarification 控制工具。
- 一套上述虚构输入资料与确定的数值基线。
- 可查看的运行事件、成功产物与失败/停止原因。
- 核心循环测试、工具测试及真实模型实验记录。
- 明确的限制说明：仅本地、一次一个 Run、内存状态、无崩溃续跑、无任意代码工具。

做到这些再进入第二阶段的复杂任务、规划和上下文管理，而不是立即补登录页面。若仍解释不清工具为什么被调用、结果如何回到模型，先把这一阶段打透。
